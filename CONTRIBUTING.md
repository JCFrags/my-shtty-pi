# Contributing

## Review state

`main` is the best reviewed state. It is not a promise that every package is ready for use or publication.

Use one-purpose branches and pull requests. Each pull request must include acceptance evidence that matches its scope. Keep repository administration separate from feature work. Isolate package behavior changes by package.

Do not commit generated output, dependencies, credentials, sessions, logs, machine paths, or private state. Record source provenance for copied or adapted material, and preserve required license notices.

Agents may execute approved work, but they cannot silently redefine product scope, lifecycle status, acceptance criteria, or release decisions.

## Pull request expectations

Explain the package or repository scope, purpose, files changed, behavior changed, evidence, limitations, and deployment effect. Separate repository merge decisions from package readiness and publication decisions.

Run the smallest relevant offline checks first. Do not install dependencies, publish packages, deploy changes, or change GitHub administration as part of routine contribution work.
